# Factory — autonomous issue→PR pipeline (new "Factory" tab)

Superset's take on Vercel's [`ai-sdk-factory`](https://vercel.com/blog/building-a-software-factory-for-ai-sdk)
and Mastra's Factory (hands-on E2E report: `mastra-factory-report.md` in the
`mastra-factory-research` worktree): GitHub issues flow through per-stage agents
(classify → analyze → implement → review) to a human-gated PR, with pipeline visibility
and a feedback loop that improves stage prompts.

**Differentiator:** stages run on the user's own hosts via existing Superset workspaces —
local-first, any CLI agent per stage. Vercel needs their sandbox cloud; Mastra walked away
from desktop entirely.

## Borrowed patterns

From **Vercel**: one agent per stage (own prompt/model/evals) · every run ends
`success | flawed | blocked | manual`, non-successes drive improvements · human merge gate.

From **Mastra** (verified in our E2E run): agents move the board via a CAS transition tool
with written rationale · materialization keys for idempotent intake · decision ledger
(typed, retryable, `lastError`, in UI) · completion ≠ merge (post-merge verify pass) ·
stage-age health thresholds in metrics.

**Mastra anti-lessons** (bugs we hit): intake fired only on board *view* — ours must be
webhook + background poll · their execute stage never auto-started — every transition must
enqueue the next stage · sessions spawned silently with an uncredentialed model — validate
stage agent config at dispatch, fail loudly.

## Architecture

```
GitHub webhook / poll ──► factory_items (materialization key)      [webhook infra exists]
      └► QStash ──► dispatchFactoryStage()                         [copy dispatchAutomation]
                      └► workspaces.create + agents.run on host    [exists]
agent ──► MCP factory_report: typed result + outcome + CAS stage transition + rationale
      └► next stage enqueued (or human gate)
Factory tab reads items/runs via new cloudTrpc factory router
```

`packages/trpc/src/router/automation/dispatch.ts` is the stage-runner template end-to-end
(host presence, scoped JWT, dedup run row, `dispatch_failed`, workspace deep-links).

## Data model (packages/db, cloud)

- **`factories`** — org, project (repo), targetHostId?, enabled, trust rules, per-stage
  agent preset + model.
- **`factory_items`** — source issue/PR, `materializationKey` (unique), `stage`
  (`intake → classify → analyze → implement → review → human_review → verify → done | rejected`),
  `revision` (CAS), prUrl?, blockedReason?.
- **`factory_runs`** — item, stage, promptVersionId, host/workspace/session refs (mirror
  `automation_runs`), dispatch status, `outcome`, `resultJson` (per-stage zod schema),
  `rationale`, `feedbackNote?`. This is the decision ledger / evidence chain.
- **`factory_stage_prompts`** — versioned per stage (`active|draft|archived`, authoredBy
  human|agent, sourceRunIds) — pattern from `automation_prompt_versions`.

## MCP `factory_report`

`factory_report({ itemId, runId, expectedRevision, outcome, result, rationale })` — validates
against the stage schema, CAS-advances the item, enqueues next stage. Agent `Stop` without a
report → run `blocked`, item needs-attention. Replaces terminal-snapshot scraping.

## Factory tab (apps/desktop)

Exact recipe from commit `61f941071`: route dir `_dashboard/factory/`, sidebar buttons
(collapsed + expanded), `onDashboardViewRoute` + `hideTopBar`, new `factory` router mounted
in `root.ts` + `CLOUD_TRPC_ROUTER_ROOTS`.

Views: **pipeline board** (columns = stages, kanban components; header: throughput,
stage-age health, 7d outcome mix) · **item detail** (evidence chain of runs, deep-link into
each run's workspace/session) · **stage settings** (prompt + version history, agent, pause) ·
**improve view** (phase 3).

## Self-improvement (phase 3)

Human marks runs `flawed` + note (auto-flawed on unmerged-close or classification override) →
accumulated flawed runs dispatch an **improve run**: meta-agent reads flawed transcripts +
notes + current prompt, drafts a new prompt version + eval case → human approves in UI →
active. Eval replay against drafts = phase 4.

## Phasing

1. **Skeleton (demoable):** schema; tab + board + item detail; manual intake (existing
   `search-github-issues`); classify + analyze stages; `factory_report`; run-now dispatch.
2. **Autonomous loop:** `issues.opened` webhook + backfill poll; implement + review stages;
   draft PRs; merge → verify → done; outcomes.
3. **Self-improve:** flawed feedback, versioned prompts, improve runs, approval flow.
4. **Hardening:** eval replay, backports, trust expansion.

## Decisions (recommended)

1. State lives **cloud-side** (webhooks + tab are cloud; hosts stay execution-only).
2. `factory_items` separate from `tasks` (task statuses are org-editable; stages are fixed).
3. Ship ungated behind a feature flag to the internal org first.
4. Retries = explicit attempt counter; never silently retry implement runs.
