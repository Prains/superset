Executive summary

Superset's onboarding is already one of the leanest in the set — two steps, one required decision, zero survey questions — and its live-detecting dependency checklist and embedded gh auth terminal are better than anything in the captures. The gaps are elsewhere: our sign-in screen is dead air while every winner demos the product during auth; our "aha" (an agent actually working) is never shown during onboarding; our GitHub ask has no trust copy; and steps a user skips vanish forever because onboarding is a one-way gate.

Screens between the primary CTA and a usable product surface (OAuth happy path, approximated from captures)

Lower is faster, but not automatically better — Linear spends its extra screens on habit formation (⌘K, shortcuts, GitHub) rather than data collection. Cursor's flow ends at a desktop-download wall rather than the product itself.

Superset — our current flow

Mapped from code (no Mobbin capture exists for us). Brand-new-user path: splash → browser OAuth → auto-created personal org → a two-step full-screen wizard → workspaces dashboard with the composer pre-opened.

1

Sign-in

Full-screen: logo, "Welcome to Superset", Continue with GitHub / Continue with Google, "Last used" badge on the previous method, ToS footer. Auth is a browser round-trip: the default browser opens, the web success page mints a desktop session, and a superset:// deep link returns the token. During that round-trip the app shows nothing but the sign-in screen.

2

Org creation (invisible)

A personal org ("<Name>'s Team") is auto-provisioned server-side, or the user is auto-enrolled by email domain. The "Create Organization" screen exists only as a fallback.

3

Step 1 of 2 — "Setup Superset"

A live-detecting checklist polling every 4s: GitHub CLI (badge "Required", but not enforced), Claude Code, Codex. The gh row opens a modal with a real embedded PTY that runs gh auth login, scrapes the one-time code, auto-copies it, and auto-opens the browser. Agent rows open OAuth-or-API-key dialogs. Everything is skippable; Continue is never disabled.

4

Step 2 of 2 — "Create or add a project"

Four cards: Create new / Open a folder (with git-init prompt) / Clone a repo (inline, with actionable auth errors that open the gh dialog) / Start from a template (gstack, Next.js, T3, Expo…). Not skippable — adding a project is the completion event. This is the flow's single required decision.

5

Completion → composer

onboarded_at is set (one-way — no UI re-entry ever), then the user lands on the workspaces dashboard with the "What should we build next?" composer pre-opened on the new project, an agent auto-selected, and three sample prompts ("Set up this project for Superset", "Explain how this repository works", "Find a small bug and fix it"). No completion moment, no tour, no checklist.

Already best-in-class

  • Live-detecting dependency checklist — statuses flip to Connected as the user installs or signs in from anywhere, even an external terminal. Nobody in the capture set does environment setup this gracefully.
  • Embedded gh auth terminal — code scraped, auto-copied, browser auto-opened. Strictly better than every "go run this command" pattern.
  • Zero survey questions and a two-dot wizard — matches the choice made by Cursor, Claude, Linear, and Railway.
  • Actionable clone errors — SSH/private-repo failures render an inline "Sign in to GitHub CLI" fix, not a toast.

Gaps vs. the field

  • Sign-in is dead air. The browser OAuth round-trip is our slowest moment and the screen shows a logo and two buttons. Every winner uses this exact moment to demo the product.
  • The aha is never shown. No agent runs during onboarding; sample prompts appear only after, as passive chips.
  • No trust copy on the GitHub ask. "Clone, push, and create PRs" + a "Required" badge, with no statement of what we don't touch.
  • One-way gate. Skipped agent connections never resurface; there is no re-entry into onboarding and no post-onboarding recap.
  • No completion beat. Jump-cut from project step to composer with no "you're good to go" or shortcut teaching.

Recommendations

Ranked by leverage. The first three touch every new user.

1. Animate the sign-in / OAuth wait with a product simulation

Our slowest moment — the browser round-trip — is exactly where Claude runs its agent demo and Railway shows its deployed canvas. Show agents fanning out across parallel worktrees, statuses ticking, and PRs landing while the user authenticates.

Pattern source: Claude 01–03, Railway 02–05, Lovable 03–06

2. Add a guided "see it work" first task at completion

Make the existing "Explain how this repository works" sample prompt the celebrated default action right at onboarding completion — one button that actually launches an agent — instead of one of three quiet chips the user may never notice.

Pattern source: Claude 05–06 ("See it work"), Linear 12 (⌘K performed live), Linear 18

3. Add trust copy to the GitHub CLI step

State plainly what we never do (e.g. "everything runs locally — your code never goes through our servers", phrased to match reality). Linear's "will not ask for code read permissions" line is the model. Cheap copy change, real conversion impact on the scariest ask.

Pattern source: Linear 13

4. Resurface skipped setup after onboarding

onboarded_at is a one-way gate today. Add a dashboard "finish setup" affordance (or a Linear-style recap) so a user who skipped Claude Code / Codex connection isn't left to find Settings alone.

Pattern source: Cursor 13 (dashboard re-offer), Linear 17 (recap cards)

5. Add a completion beat

A single "You're good to go" moment that names what just happened and teaches one shortcut, before the composer appears. Railway's handoff toast ("You may now proceed with your deployment!") is the minimal version.

Pattern source: Linear 17, Railway 11

Keep: the live checklist, the embedded gh terminal, zero questions, two steps

These already match or beat the field. Don't add segmentation questions, don't add a paywall, don't lengthen the wizard.

Avoid: Lovable's 4-question quiz and Cursor's pre-product paywall

Every other dev tool in the set asks 0–1 questions. And a paywall before first value only works with Cursor's brand recognition.
